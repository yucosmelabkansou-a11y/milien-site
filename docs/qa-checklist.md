# Milien — QA checklist

## 実施方法と判定

**QAの深さは変更範囲に合わせる。**

- 文書のみ：文書QA
- コピー／HTMLの小変更：Content + HTML + 関連画面
- CSS／JS／フォーム変更：関連項目 + PC/mobile画面QA
- 共通部品／公開前：原則フルQA

変更と無関係な項目を機械的に全実行しない。

サイト実装を変更したら、指示を待たずに本書の該当検証を行う。
検証は正本の作業版をローカルpreviewで行い、公開版との結果を混ぜない。

各項目を次のいずれかで報告する。
- PASS：実行して条件を満たした
- FAIL：実行して問題を確認した
- 未実施：実行できていない。理由と影響を書く
- N/A：変更内容に対して対象外。理由を書く

変更前からある問題と、今回追加した問題を区別する。
既知のFAILを無断で修正範囲へ追加しない。
ただし、成功条件に関わるFAILを残して「完了」としない。

文書だけの変更では、参照先、内容の矛盾、旧指示の残存、
差分範囲を確認する。画面・フォームQAはN/Aと理由を記す。

## 0. 準備

- [ ] 正本、branch、HEAD、既存差分を記録した。
- [ ] 公開版／main／作業版を区別した。
- [ ] READMEにある実在する起動・検証方法を確認した。
- [ ] 変更前の画面・挙動を、変更後と比較できる条件で確認した。
- [ ] 対象ページ、ブラウザ、viewport、成功条件を決めた。

現在は静的HTML／CSS／JSで、npm test・lint・buildの設定はない。
存在しないコマンドを実行済み・合格と記載しない。

## 1. Content

- [ ] content-guidelines.mdの正式サービス名と役割に一致する。
- [ ] 旧サービス名が、現在のサービス説明・CTA・フォームに残っていない。
- [ ] HERO、本文、FAQ、会社紹介、フッター、メタ情報が矛盾しない。
- [ ] 同じ抽象語・説明を不自然に繰り返していない。
- [ ] 対応範囲と非対応範囲がFlow・FAQ・フォームでも一致する。
- [ ] 料金、期間、返信期限、成果保証を独断で追加していない。
- [ ] 実績・数値・経歴に確認可能な根拠がある。
- [ ] 資料サンプルと実績下書きを実案件として表示していない。

検索は公開対象ファイルと履歴資料を分けて行う。
語の出現件数だけで合否を決めない。

## 2. HTML・アクセシビリティ

HTML解析とブラウザDOMで確認する。文字列検索だけで合格にしない。

- [ ] IDが一意。company等、sectionとinputの衝突もない。
- [ ] labelのforが対応する入力要素を指す。
- [ ] 入力欄・ボタン・リンクに理解できる名前がある。
- [ ] h1とh2以降が内容の階層を表す。見た目だけで見出し段階を選んでいない。
- [ ] header／nav／main／section／article／footer等を適切に使っている。
- [ ] 画像のaltが適切。装飾は不要な読み上げをしない。
- [ ] aria-controls等の参照先が存在し、状態属性が実際の開閉に一致する。
- [ ] 内部アンカーが存在する。別ページからのアンカーも到達する。
- [ ] Tab／Shift+Tab／Enter／Spaceで主要操作ができ、focusが見える。
- [ ] 閉じた領域に操作可能な要素が取り残されない。
- [ ] メニューの終了操作とフォーカス移動・復帰を確認した。
- [ ] 文字拡大200%で情報と機能が失われない。
- [ ] 通常文字4.5:1、大きな文字3:1を基準にコントラストを確認した。
- [ ] 色・hover・アイコンだけに重要情報を依存させていない。

## 3. CSS・レスポンシブ

サイト変更時の基本確認：
- Desktop：1440×900
- Tablet：768×1024
- Mobile：390×844

変更が関連する場合は1023／1024、767／768、480px前後、
375px、小画面、横向きも確認する。

- [ ] 意図しない横スクロールがない。
- [ ] 見出し、長文、英語、URLがはみ出さない。
- [ ] 不自然な一文字改行や、文字を縮めすぎた箇所がない。
- [ ] 固定ヘッダーがアンカー先を隠さない。
- [ ] CTA同士、CTAと本文、CTAとフォームが重ならない。
- [ ] mobile下部CTAがContact付近で消える。
- [ ] ソフトウェアキーボード表示時も入力・送信操作を妨げない。
- [ ] サービス詳細、FAQ、資料サンプルが開閉・拡大で崩れない。
- [ ] 画像の比率・トリミングと情報密度が自然。
- [ ] hover／focus／disabledの各状態で読める。
- [ ] reduced motion設定とJavaScript不成立時の本文可視性を確認した。

CSSの冒頭値だけで判断せず、最終的な適用値を確認する。
printは、印刷変更がGoalにある場合以外は低優先とする。

## 4. JavaScript

- [ ] js/main.jsの構文確認を行った。現在の例：node --check js/main.js
- [ ] ページ読込後と各操作後のconsole errorを確認した。
- [ ] CSS／JS／画像等の読み込み失敗を確認した。
- [ ] mobile menuの開閉、リンク選択後の閉じ方、aria-expandedが正しい。
- [ ] FAQの閉→開→閉と、別項目を開いた時の動作が正しい。
- [ ] サービスのdetailsとFAQを別機能として確認した。
- [ ] PCで常時表示するdetails本文が、Safariを含め実際に読める。
- [ ] smooth scrollが通常アンカー・ページ先頭・空の#でエラーにならない。
- [ ] 浮遊CTAと現在位置のナビ表示が正常。
- [ ] 変更した共通JSが、フォームのない下層ページでも失敗しない。

ブラウザが利用できない場合、構文確認だけで操作QAを合格にしない。

## 5. Form

基本の送信先・送信項目は既存実装を確認して維持する。

- [ ] 必須項目：氏名、会社名、メール、相談内容、privacy同意。
- [ ] 空欄、空白だけの入力、不正なメール、同意なしを確認した。
- [ ] 任意項目が意図せず必須になっていない。
- [ ] selectの初期値・選択肢・送信値が正しい。
- [ ] checkboxが複数選択でき、既存選択を不要に消さない。
- [ ] 各サービスCTAのdata-presetが対応するcheckboxのvalueと一致する。
- [ ] 3つのサービスCTAをそれぞれ操作して、対応する選択がONになる。
- [ ] company等のID変更時はlabel・JS・アンカーへの影響も確認した。
- [ ] privacyリンクが開き、入力情報の取り扱い説明と矛盾しない。
- [ ] 送信中の二重操作防止、成功表示、失敗表示、再試行を確認した。

Formspreeへは実際に送信される。
通常QAでは本送信しない。

送信処理を検証する場合は、ローカルpreviewで外部POSTを
ネットワーク層で捕捉・遮断し、成功／失敗応答を模擬する。
遮断を確認できない環境では送信ボタンを押さず、未実施と報告する。
実送信は、その試験についてユーザーが明示許可した場合のみ行う。

## 6. SEO・リンク・共通ページ

- [ ] title、description、OGPがページ内容と一致する。
- [ ] canonicalとog:urlが正しい公開URLを指す。
- [ ] OGP画像が存在する。
- [ ] JSON-LDが構文として有効で、本文の会社・サービス・著者情報と一致する。
- [ ] robots.txtとsitemap.xml、実際のページ構成に不整合がない。
- [ ] sitemapの更新日は、意味のある内容更新に基づく。
- [ ] 内部リンク、画像、アンカーが切れていない。
- [ ] 新規の外部リンクは参照先を確認した。

共通CSS／JS／ヘッダー／フッターを変更した場合は、
トップ、privacy、コラム2ページ、404への影響も確認する。
キャッシュ番号は参照している全ページで確認し、
古いアセットと新しいHTMLが組み合わされないようにする。

## 7. 最終画面確認

- [ ] PCと390pxの変更前後スクリーンショットを比較した。
- [ ] ページ全体と、変更箇所・メニュー・開いた詳細・フォームを確認した。
- [ ] アニメーション途中の画像を完成画面として判定していない。
- [ ] コード上は正しくても、余白、改行、色、密度が不自然な箇所を確認した。
- [ ] 使用ブラウザを記録し、実機確認と画面幅エミュレーションを区別した。

スクリーンショットを撮っただけでは完了ではない。
画像を実際に確認し、気づいた問題と判断を記録する。
