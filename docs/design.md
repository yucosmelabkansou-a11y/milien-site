# Milien — Design guidelines

## 基準

温かい白・グレージュ、落ち着いたプラム、細い線、
日本語の明確な見出しと十分な余白を軸にする。

現サイトの良い部分を保つための文書であり、新しい意匠を足すための仕様ではない。
ブランド・サービスの文章はcontent-guidelines.mdを参照する。

以下の数値は2026-09-09に確認した公開表示と8月26日作業版の基準値。
実際の適用値はcss/style.cssとブラウザのcomputed styleで確認する。
意図的に基準を変える場合は、承認のうえ実装と本書を合わせて更新する。

## 色

| 用途 | 基準 |
|---|---|
| 基本背景 | #FAF8F6 |
| サブ背景 | #F2EFEC |
| 補助色 | #B9A2A6：ローズグレージュ |
| CTA・主要強調 | #5B2F42：ディーププラム |
| 濃いhover色 | #43222F |
| 本文 | #2A2529 |
| 補助本文 | #63595C |
| 罫線 | #E2DCD9 |

背景の切り替え、罫線、余白で情報を区切る。
プラムを全画面へ広げず、行動・重要情報を示すために使う。
淡い色を小さな本文に使う場合は、可読性をQAで確認する。

主CTAは単色。
既存の淡い背景グラデーションやヘッダー限定の透過表現を、
「グラデーション禁止」を理由に一括削除しない。

## 書体・見出し

- 日本語・本文：Noto Sans JP。
- 英字ロゴ・補助ラベル・数字：Cormorant Garamond、fallbackはGeorgia等。
- 日本語を理解の主役にする。英語は区分と雰囲気を補助する。
- 英語ラベルは小さめで字間を取り、日本語見出しより強くしない。
- PCのH1は約2.05rem、mobileは約1.42remが現行基準。
- 一般セクション見出しはPC約1.8rem。
  mobileは幅に応じ約1.35rem／1.24rem。
- 本文は概ねline-height 1.7〜1.95。詰めるために文字を小さくしない。
- 改行は意味のまとまりを優先する。390pxで一文字だけ残る改行も目視する。
- 既存HEROの言葉を、行数合わせのために書き換えない。

## 横幅・余白

- 共通コンテナはmax-width 1100px、PC左右32px。
- mobileの一般コンテナは左右20px。
  小画面HEROは左右16pxという既存差異がある。
- 長文リードは760px程度、Contact内側は780px程度。
- 共通セクションは上下88px、mobile64pxが基準。
- 見出しと本文の間は44px、mobile32pxが基準。
- Issue／Position／Service等には圧縮した個別指定がある。
  例：公開IssueはPC68px、390px時44px。
- 全セクションを同じ余白へ機械的に統一しない。
- 「何画面以内」という過去の目標は恒久仕様にしない。

## 情報の見せ方

内容に合う形を選ぶ。
- 悩みと変化：対応関係のある行
- Milienの役割：流れを示す図
- サービス：範囲と相談導線が分かるプラン
- 成果物：紙面のイメージと説明
- 理由：写真と具体的な能力
- 会社概要：表形式
- コラム：リスト

同じカードを連続させない。
概要だけで役割が分かり、詳細を読むと範囲が分かる密度にする。
長文を追加する前に、重複した説明がないか確認する。

## カード・線・角丸

- サービス枠は白地、1pxの罫線、6px程度の角丸。
- 資料紙面等は3px程度の小さな角丸と控えめな影。
- 線は主張させず、区切りや関係を示すために使う。
- フォーム、FAQ、丸い番号、PC浮遊CTAには既存の例外がある。
- 全要素へ一律の角丸上限を適用しない。
  新規要素は同じ役割の既存部品に合わせる。
- 非クリック要素を、押せるカードのように演出しない。

## ボタン・CTA

- 主CTA：プラム単色＋白文字。
- 副CTA：プラムの枠線＋背景を活かす。
- 一般ボタンの角丸は2px程度。
- CTAの言葉はcontent-guidelines.mdに従う。
- mobileのHERO CTAは縦並び・全幅を基本にする。
- サービスCTAは対応する問い合わせ選択肢へつなげる。
- 既存の固定ヘッダー、PC右下CTA、mobile下部CTAを尊重する。
- Contact付近で浮遊CTAを隠し、フォーム操作を妨げない。

## 写真・アイコン

- 代表写真は実際の本人写真を使い、既存の落ち着いたトリミングを保つ。
- 現行写真枠は4:5、角丸6px程度。円形への変更を標準にしない。
- 一般的な美容ストック写真や架空の人物で置き換えない。
- アイコンは細い線画、矢印、番号を中心に、意味がある場所だけに使う。
- 装飾アイコンは読み上げに混ぜず、重要情報をアイコンだけで伝えない。

## Desktop / mobile

- 主な境界は1023px／767px／480px。
- 横並びの関係を、mobileでは理解できる順番の縦並びへ変える。
- 作業版のService 02・03はPC2列、1023px以下1列。
- 資料サンプルは3列→2列→1列。
- PCで表示する詳細と、mobileで折り畳む詳細を区別する。
- 767／768px境界で本文が見えなくならないことを確認する。
- hoverがなくても情報と機能へ到達できるようにする。

## Animation / hover

- 現在の短いフェード・小さな移動を参考にする。
- ボタンの濃色化、控えめな浮上、リンクの下線、
  コラム行の背景変化程度に留める。
- 動き自体を主役にしない。内容を読むために長く待たせない。
- reduced motionとJavaScript不成立時の可読性はQAで確認する。
- 現在の未対応や不具合を、守るべきデザインとして固定しない。

## 避ける方向

- 紫・青の強いグラデーションを中心としたAI SaaS風の表現
- ガラス表現の多用
- 全セクションのカード化
- 意味のないアイコン・装飾・大きな角丸の追加
- 派手な反復アニメーション、パララックス
- 甘い美容広告のような写真・コピーへの寄せすぎ
- 無機質なSaaS管理画面のような密度
- 文字の詰め込み、読みにくい薄色、小さな本文
- 理解や操作に寄与しない意匠変更
